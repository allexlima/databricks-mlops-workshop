Fundamentos

O que é MLOps?

A disciplina de ciclo de vida que leva um modelo do notebook a um artefato confiável, versionado e governado. Não é sobre infraestrutura sofisticada.

  • Gerencia dados, código e modelos como um sistema
  • Reduz risco técnico e de compliance
  • Automatiza e padroniza a entrega

Fundamentos

Por que MLOps importa

Menos risco

Modelos frágeis, dados que mudam e exigências de compliance viram riscos controlados, com validação e governança em cada etapa.

Mais eficiência

Automação e padronização encurtam o caminho até produção e eliminam processos manuais, lentos e difíceis de repetir.

Mais confiança

O time entrega e itera sem vigiar modelos na mão, com rastreabilidade do dado até a decisão.

Pilar 1 · em código

Tracking em uma linha

train.py Python 
import mlflow
mlflow.autolog()                       # sklearn, XGBoost, PyTorch, …

with mlflow.start_run(run_name="baseline"):
    model.fit(X_train, y_train)        # params, métricas e modelo: logados
    score = model.score(X_test, y_test)
    mlflow.log_metric("test_score", score)

Uma linha instrumenta o treino inteiro. Compare runs na UI: qual a melhor versão? o que mudou?

Pilar 2 de 4 · Governança (pro)

Do básico ao pro

Versões & Aliases

@champion · @challenger

Cada registro vira v1, v2, v3… Carregue por alias mutável, nunca por número, e re-execuções não quebram nada.

Pilar 3 de 4 · muito importante

PyFunc: a língua franca do MLflow

  • Cada framework tem seu flavor: sklearn, pytorch, …
  • E quando não há flavor? Quando não há fit()?
  • Qualquer objeto com predict() vira modelo governado
  • Todo flavor nativo é construído sobre PyFunc
Solver de OR, motor de regras, heurística, simulação: tudo cabe

Pilar 3 · em código

Empacote qualquer modelo

my_lib.py Python 
class MyModel(mlflow.pyfunc.PythonModel):
    def predict(self, context, model_input, params=None):
        return run_my_logic(model_input)   # regras, solver, heurística…

mlflow.pyfunc.log_model(
    name="model",                          # MLflow 3.x: name=, não artifact_path=
    python_model=MyModel(),
    code_paths=["./my_lib.py"],          # empacota o código junto
    registered_model_name="catalog.schema.my_model",
)

No Lab 3, o exemplo é um solver de pesquisa operacional (Pyomo), sem fit(), governado como qualquer modelo. O modelo é só um exemplo. O que importa é o padrão.
